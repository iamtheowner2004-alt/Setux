1. PROJECT OVERVIEW & CORE OBJECTIVES
================================================================================

The Societal Innovation AI Agent Platform is an end-to-end multi-agent system
designed to automate and streamline the resolution of real-world civic and
societal challenges across India.

The platform creates a unified, closed-loop collaboration ecosystem bridging four
primary entities:
  1. Citizens (who report grassroots societal challenges)
  2. Universities / Higher Education Institutions (who provide research, faculty,
     and student innovation to design solutions)
  3. Industry Partners / MSMEs / CSR Bodies (who provide manufacturing, funding,
     technology, testing, and deployment at scale)
  4. Government Authorities (who intervene and provide statutory or financial
     support when industry partnerships are unavailable)

Core Objectives:
- Eliminate duplicate problem reporting using dense semantic embeddings.
- Automatically extract domain categories, priority scores, and academic queries.
- Dynamically query real academic bibliographic indexes (OpenAlex) to identify
  the most qualified Indian universities and research institutions.
- Facilitate admin-in-the-loop human oversight before initiating outbound
  communications.
- Leverage real-time web searches and LLM reasoning to identify authentic Indian
  industry partners capable of implementing university solutions.
- Implement automated escalation workflows to government bodies when private
  sector adoption fails, ensuring no citizen problem is left unaddressed.

2. COMPLETE TECH STACK: WHAT IS USED & WHY IT IS USED
================================================================================

1. PYTHON 3.10+
   - What it is: High-level, dynamically typed programming language.
   - Why it is used: Python is the standard language for AI/LLM engineering,
     offering rich asynchronous support, clean syntax, and top-tier client
     libraries for machine learning, web APIs, and database drivers.

2. FASTAPI
   - What it is: Modern, high-performance web framework for building APIs with
     Python 3.8+ based on standard Python type hints.
   - Why it is used:
     * Asynchronous execution (ASGI): Built on Starlette, allowing non-blocking
       I/O for AI calls, database operations, and external network requests.
     * Automatic interactive documentation: Generates interactive Swagger UI
       (/docs) and ReDoc (/redoc) schemas automatically.
     * High developer velocity and strict type safety via native Pydantic integration.

3. UVICORN (STANDARD)
   - What it is: Lightning-fast ASGI web server implementation for Python.
   - Why it is used: Serves the FastAPI application using uvloop and httptools,
     providing optimal throughput and low latency under concurrent traffic.

4. PYDANTIC (V2)
   - What it is: Data validation and settings management library using Python type
     annotations.
   - Why it is used:
     * Validates incoming HTTP payloads before reaching router handlers.
     * Enforces structural integrity on complex data models (ProblemRequest,
       SolutionRequest, UniversityCreate, IndustrySearchRequest).
     * Prevents invalid data from entering the database or AI prompt pipelines.

5. MONGODB & PYMONGO
   - What it is: Document-oriented NoSQL database and its official Python driver.
   - Why it is used:
     * Schema flexibility: AI outputs (nested JSON, arrays of search results,
       variable metadata from OpenAlex and web scraping) vary significantly in
       structure. MongoDB handles deeply nested hierarchical JSON documents natively.
     * Scalability and query simplicity: Fast lookups and in-place document updates
       for workflow state transitions (updating arrays of recommendations, status
       flags, and timestamps).

6. GOOGLE GENAI SDK (`google-gen-ai`) & GEMINI MODELS
   - What it is: Google's official client library for Gemini generative AI models.
   - Models Used:
     * `gemini-3.6-flash`: Utilized for prompt-driven text generation, problem
       analysis, solution viability assessment, industry candidate evaluation,
       and government report drafting.
       Why used: Fast inference speed, high context reasoning, and reliability in
       strictly outputting valid JSON without hallucinated formatting.
     * `gemini-embedding-001`: Utilized for generating text embeddings.
       Why used: Converts problem text into dense vector representations to perform
       semantic similarity matching and deduplication.

7. OPENALEX API (`https://api.openalex.org`)
   - What it is: Free, open, and fully indexed bibliographic catalog of global
     scientific research papers, authors, institutions, and concepts.
   - Why it is used:
     * Grounds academic institution recommendations in real, verifiable scientific
       literature rather than static or hallucinated lists.
     * Allows precise geographic filtering (`institutions.country_code:IN`) to target
       Indian universities with demonstrated publication history in specific problem areas.
     * Provides institution metadata (ROR IDs, official homepage URLs, works counts,
       and total citations).

8. DUCKDUCKGO SEARCH (`ddgs` / `duckduckgo_search`)
   - What it is: Python library for executing DuckDuckGo search queries programmatically.
   - Why it is used:
     * Provides live, real-time web search capabilities to discover active Indian
       companies, MSMEs, startups, and NGOs based on solution technologies.
     * Free and requires no proprietary paid API keys, preventing vendor lock-in.

9. FASTAPI-MAIL & AIOSMTPLIB
   - What it is: Asynchronous mail sending wrapper for FastAPI using standard SMTP.
   - Why it is used:
     * Sends automated email invitations to university administrators and nodal officers.
     * Asynchronous execution ensures sending an email does not block worker threads
       or delay API responses.

10. PYTHON-DOTENV
    - What it is: Environment variable loader from `.env` files.
    - Why it is used:
      * Adheres to Twelve-Factor App security guidelines by keeping database connection
        strings, API keys, and mail passwords outside the source code.

11. HTTPX
    - What it is: Modern, fully featured HTTP client for Python with sync and async support.
    - Why it is used:
      * Makes clean, resilient HTTP calls to OpenAlex endpoints with configurable
        timeouts and error status checking.

12. BSON / OBJECTID
    - What it is: Binary JSON library bundled with PyMongo for unique identifier handling.
    - Why it is used:
      * Validates, encodes, and decodes 12-byte / 24-hex-character MongoDB ObjectIds
        across all router endpoints.

4. DETAILED END-TO-END SYSTEM WORKFLOW & DATA LIFECYCLE
================================================================================

--------------------------------------------------------------------------------
PHASE 1: Problem Ingestion, AI Analysis, Deduplication & Academic Discovery
--------------------------------------------------------------------------------
1. Citizen submits a problem via `POST /api/ai/analyze-problem` containing:
   - title, description, location.

2. AI Analysis (`app/services/problem_analyzer.py`):
   - Prompt sent to `gemini-3.6-flash` instructing it to return strict JSON.
   - Computes: summary, category, subcategory, severity, priority score (1-100),
     keywords, required expertise, and 3-5 academic research queries tailored for India.

3. Semantic Duplicate Detection (`app/services/duplicate_detector.py`):
   - Generates a 768-dimensional vector embedding for `"title. description"` using
     `gemini-embedding-001`.
   - Iterates through all existing problems in MongoDB, computing Cosine Similarity
     between new vector and stored vectors.
   - If similarity >= 85%:
     * Returns immediate response indicating duplicate detected, along with matching
       problem IDs and similarity scores. Workflow terminates here.

4. OpenAlex Academic Discovery (`app/services/university_agent.py`):
   - For each generated academic research query, queries OpenAlex API with
     `filter=institutions.country_code:IN`.
   - Extracts Indian institutions and paper titles, aggregating citation/work counts.
   - Merges institution records across multiple queries to build a composite research profile.

5. Filtering & Enrichment (`app/services/university_filter.py` & `official_source_verifier.py`):
   - Runs heuristic keyword filtering (whitelisting "university", "IIT", "NIT",
     "institute of technology" while blacklisting "hospital", "pvt ltd", "company").
   - Enriches institutions via OpenAlex Institutions endpoint to fetch official website URLs,
     ROR IDs, works counts, and type.

6. Ranking & Scoring (`app/services/university_matcher.py`):
   - Computes a match score (0-100) based on:
     * Relevant papers found (up to 60 pts)
     * Official website availability (20 pts)
     * Research volume / activity (up to 20 pts)
   - Sorts institutions in descending order and selects the Top 5 candidates.

7. Database Persistence:
   - Stores problem document in `problems` collection with status `"pending_admin_review"`.

--------------------------------------------------------------------------------
PHASE 2: Admin University Review, Email Dispatch & University Decision Loop
--------------------------------------------------------------------------------
1. Admin fetches pending problems via `GET /api/admin/problems/pending`.
   - Retrieves all problems with status `pending_admin_review` or `pending_next_university`.

2. Admin Approves a University via `POST /api/admin/problems/{id}/approve-university`:
   - Validates the selected university index.
   - Updates the chosen university's status to `"approved"`.
   - Updates the problem document's status to `"approved_for_university_outreach"`.

3. Email Preview & Dispatch (`app/services/email_service.py` & `app/routers/admin.py`):
   - Admin previews generated email via `GET /api/admin/problems/{id}/university-email-preview`.
   - Admin sends email via `POST /api/admin/problems/{id}/send-university-email`.
   - Asynchronous SMTP sends an official outreach letter inviting the university to form a
     student-faculty team.
   - Problem status transitions to `"university_contacted"`.

4. University Responds via `POST /api/universities/problems/{id}/respond?response=accept|decline`:
   - IF ACCEPTED:
     * Selected university marked `"accepted"`.
     * Problem status transitions to `"university_accepted"`.
   - IF DECLINED:
     * Selected university marked `"declined"`.
     * System checks for the next pending university in the ranked recommendations.
     * If next university exists:
       - Status updates to `"pending_next_university"`, pointing to the new candidate.
       - Admin can review and dispatch email to the subsequent candidate.
     * If all recommended universities have declined:
       - Status transitions to `"all_universities_declined"`.

--------------------------------------------------------------------------------
PHASE 3: University Solution Submission & AI Real-Time Industry Matching
--------------------------------------------------------------------------------
1. Once a university develops a solution, it is analyzed via `POST /api/ai/find-industries`
   (or evaluated via `POST /api/ai/analyze-solution`).
   - Request includes `problem_id`, `solution_title`, `solution_description`, and `technologies`.

2. Solution Analysis (`app/services/solution_analyzer.py`):
   - `gemini-3.6-flash` analyzes the solution against the original problem.
   - Computes: relevance score (0-100), status (promising/partially_relevant/not_relevant),
     strengths, limitations, implementation needs, required industry sectors, and
     3 to 5 targeted Indian industry web search queries.

3. Real-Time Web Search (`app/services/industry_search.py`):
   - Executes DuckDuckGo text searches for each AI-generated query.
   - Collects live web results (page titles, URLs, snippets/descriptions), deduplicating by URL.

4. AI Industry Partner Ranking (`app/services/industry_matcher.py`):
   - Feeds the original problem, solution analysis, required sectors, and raw web search
     candidates into `gemini-3.6-flash`.
   - AI evaluates ONLY the real candidates provided (strict anti-hallucination rules).
   - Generates scores, relevance to India, explanation, and possible contributions.
   - Rejects non-viable candidates with stated reasons.

5. Database Persistence:
   - Saves record into `industry_recommendations` collection with status `"pending_admin_review"`.

--------------------------------------------------------------------------------
PHASE 4: Admin Industry Approval, Outreach & Industry Response Loop
--------------------------------------------------------------------------------
1. Admin fetches pending industry recommendations via
   `GET /api/admin/industry-recommendations/pending`.

2. Admin Approves an Industry Partner via
   `POST /api/admin/industry-recommendations/{id}/approve-industry`:
   - Marks selected industry as `"approved"`.
   - Updates recommendation status to `"industry_approved"`.
   - (Alternatively, admin can reject the entire recommendation via `POST /{id}/reject`).

3. Invitation Marking via `POST /api/industry/{id}/mark-invitation-sent`:
   - Transitions status to `"industry_invited"`.

4. Industry Responds via `POST /api/industry/{id}/respond?response=accepted|rejected|not_interested`:
   - IF ACCEPTED:
     * Recommendation status transitions to `"industry_collaboration_started"`.
     * Collaborative deployment begins between University and Industry.
   - IF REJECTED / DECLINED:
     * Selected industry marked `"declined"`.
     * System checks if another pending candidate exists in `recommended_industries`.
     * If next candidate exists:
       - Status transitions to `"pending_next_industry"`, advancing the pointer.
     * If all candidate industries have declined:
       - Status transitions to `"industry_declined"`.
       - System AUTOMATICALLY triggers Government Escalation.

--------------------------------------------------------------------------------
PHASE 5: Automatic Government Escalation & Report Synthesis
--------------------------------------------------------------------------------
1. Escalation Trigger (`app/services/government_agent.py`):
   - Triggered automatically when all industries decline, or manually via
     `POST /api/government/escalate/{recommendation_id}`.

2. AI Escalation Synthesis (`gemini-3.6-flash`):
   - Reads: Original Citizen Problem, University Solution, Solution Analysis,
     and History of Declined Industry Outreach.
   - Synthesizes an executive policy report:
     * Professional Title
     * Problem & Solution Summaries
     * Outreach Failure Breakdown
     * Justification for Government Intervention
     * Concrete Action Items for Policymakers
     * Suggested Authority Level (e.g., Central Ministry, State Dept, Municipal Corp)
     * Urgency Assessment (Low / Medium / High / Critical)

3. Database Persistence:
   - Saves the generated report into `government_reports` collection.
   - Recommendation status updated to `"escalated_to_government"`.
   - Report status set to `"pending_government_review"`.

6. CORE ALGORITHMS, FORMULAS & HEURISTICS
================================================================================

1. COSINE SIMILARITY DEDUPLICATION FORMULA
   - Location: `app/services/duplicate_detector.py`
   - Formula:
                     A . B            sum(A_i * B_i)
     Similarity = ----------- = -----------------------------
                  ||A|| * ||B||   sqrt(sum(A_i^2)) * sqrt(sum(B_i^2))

   - Algorithm:
     1. Concatenate problem title and description: `problem_text = f"{title}. {description}"`.
     2. Generate dense 768-dim float vector via `gemini-embedding-001`.
     3. Compute Cosine Similarity against all existing problem embeddings in MongoDB.
     4. Convert to percentage: `similarity * 100`.
     5. Decision Rule: If `best_match["similarity"] >= 85`, mark `is_duplicate = True`.

2. ACADEMIC INSTITUTION SCORING MODEL
   - Location: `app/services/university_matcher.py`
   - Total Maximum Score: 100 Points
   - Breakdown:
     * Component 1: Related Research Papers (Max 60 points)
       Score = min(relevant_papers_count * 10, 60)
     * Component 2: Verified Official Source / Website (Max 20 points)
       Score = 20 if official_website_url exists else 0
     * Component 3: Overall Research Volume / Works Count (Max 20 points)
       - If works_count >= 10,000 -> 20 points
       - If works_count >= 5,000  -> 15 points
       - If works_count >= 1,000  -> 10 points
       - If works_count > 0       -> 5 points
       - Else                     -> 0 points
     * Final Match Score = min(Component 1 + Component 2 + Component 3, 100)

3. HIGHER EDUCATION INSTITUTION (HEI) FILTERING HEURISTICS
   - Location: `app/services/university_filter.py`
   - Whitelist Keywords:
     ["university", "institute of technology", "iit", "national institute of technology",
      "nit", "indian institute of science", "college", "school of", "academy"]
   - Blacklist Keywords:
     ["hospital", "private limited", "pvt", "ltd", "company", "corporation",
      "laboratory", "laboratories"]
   - Logic: A candidate is classified as a valid HEI if and only if it contains at least
     one Whitelist keyword AND contains ZERO Blacklist keywords.

7. AI PROMPT ENGINEERING, SAFETY & RETRY STRATEGY
================================================================================

1. STRICT JSON ENFORCEMENT
   - All prompts explicitly mandate: "Return ONLY valid JSON. Do not use markdown code fences.
     Do not add explanations before or after the JSON."
   - Cleaners parse output and strip accidental markdown blocks (```json ... ```)
     prior to `json.loads()` parsing.

2. ANTI-HALLUCINATION CONSTRAINTS
   - Industry Matcher prompt strictly enforces:
     * "Analyze ONLY the candidates provided above."
     * "Do not invent companies."
     * "Do not recommend a company unless it appears in the provided search candidates."
     * "If no candidate is suitable, return recommended_industries: [] and
        industry_search_status: 'no_suitable_industry_found'."

3. EXPONENTIAL BACKOFF RETRY WRAPPER
   - Location: `call_gemini_with_retry(prompt)` across service files.
   - Max Attempts: 3
   - Backoff Formula: `time.sleep(2 * (attempt + 1))` (waits 2s on attempt 1, 4s on attempt 2).
   - Ensures resilience against intermittent rate limits, transient network drops, or
     temporary upstream API throttling.
